# Muscle Log · iPhone 增肌训练助手 V1

这是一套可自行托管的静态 Web App（PWA），不是已上架 App Store 的原生 iPhone 应用，也不是已连接到 ChatGPT 的插件。无需数据库、账号或 API Key。

## 你的训练档案
- 21 岁，165 cm，65 kg，自报体脂约 20%，目标增肌；重点胸部、背阔肌/背宽、腿部。
- 周一/周四：胸 + 三头 + 肩中束；周二/周五：背 + 二头 + 肩后束；周六：腿；周三/周日休息。
- 胸部约 26 组/周、背部约 22 组/周：按你的反馈先维持，不因为组数高就自动削减；记录训练表现、疼痛及恢复状态以便复盘。
- 工作组一般 RIR 0，组间休息约 5 分钟，平时睡眠 8 小时以上。

## 用法
1. 选择「胸 / 背 / 腿」、训练日期及 RIR。
2. 每个动作填一次完整的训练数据，例如 `55*8 55*7 52.5*7 52.5*6`。`20*8*3` 表示 20 重量、8 次、共 3 组。`55*8@1` 表示该组 RIR 1。`3片*8*3` 表示 3 片、8 次、共 3 组。
3. 或在「一键粘贴整场记录」中粘贴多行：`Flex 胸推 55*8 55*7`，每行一动作，点击「解析并填入动作列表」。
4. 核对组数和肌群归属，保存。历史里可以复制完整记录，粘贴给 ChatGPT 分析。
5. 「趋势」可按过去 7 天统计直接组数、查看相同动作的最近两次表现、录入晨起体重和每日蛋白质估算。
6. 每隔一段时间到「设置」导出 JSON 备份；CSV 适合放入 Excel 分析。

## 在 iPhone 主屏幕使用：需先部署到 HTTPS
最简单的是 GitHub Pages：
1. 解压本 ZIP，得到 `index.html`、`sw.js`、`manifest.webmanifest`、`icon-192.png`、`icon-512.png` 等文件。
2. 创建一个 GitHub 仓库。将上面所有文件放到仓库根目录（不要只上传 ZIP）。不要将你的训练 JSON 备份或个人数据上传到仓库。
3. 进入 GitHub 仓库 `Settings` → `Pages`，选择 `Deploy from a branch`，分支 `main`，目录 `/(root)`，保存。
4. 网站上线后，在 iPhone Safari 打开 Pages 的 HTTPS 地址；点击分享 → `添加到主屏幕`，并勾选 `作为 Web App 打开`（具体文案会随 iOS 版本变化）。
5. 之后始终从同一主屏幕图标打开，保持浏览器的站点存储一致。在联网首次打开并完成缓存后，可以尝试离线访问；联网状态和系统缓存策略可能影响离线可用性。

页面本身不需要网络 API，导出文件也不需要服务器；但 PWA 安装与离线缓存通常需要 HTTPS 来源。直接双击 `index.html` 可用于电脑端预览，但 iPhone「文件」App 打开单个 HTML 文件不保证与主屏幕 Web App 等效。

## 隐私与限制
- 所有训练记录、体重、蛋白质数据默认仅在对应浏览器/Web App 的 `localStorage` 保存，不会自动同步到 iCloud、ChatGPT 或另一部设备。卸载、清理 Safari 网站数据或更换域名都有可能导致数据不可用，请定期导出 JSON。
- AI 分析不是网页内置功能；需点击「复制给 ChatGPT」并手动粘贴到聊天中。
- 未接入 Apple 健康、Apple Watch、通知、服务器、账号和云同步。
- 各肌群组数按动作主目标标签统计，不代表精确的实际肌肉刺激量。
- 不同器械或器械单位的重量不可简单横向比较。建议只对比同器械、同标准动作。
- 未经过完整 iPhone 实机测试；已使用移动视口对输入、统计和本地保存流程进行基础浏览器功能测试。

## 版本升级建议
后续可加入：历史动作自动编辑、长期动作曲线、周期性导出提醒、日历、结构化饮食扫描、带账户的端到端加密云同步。原则是先稳定记录真实数据，再升级分析能力。
